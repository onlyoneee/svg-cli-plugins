# Lab 1 Phase 2 · 第二部分：CLI 插件式重构

> 小组分工、协作流程与最终验收计划  
> 本文仅针对 **第二部分：CLI 插件式重构**；第一部分 VSCode 插件实践和第三部分 dsh 插件另行安排。  
> 作业依据：`phase_cli_2-研-1.md`（第二部分第 1–6 节及第 7 节交付与验收要求）。

## 一、任务目标

在 **Phase 1 已有 SVG CLI** 的基础上，重构出稳定的内核和可扩展的插件机制，同时保持原有命令和六种图形的兼容性。

本阶段需要完成：

- **四个扩展点**：`ShapeProvider`、`Command`、`TreeDecorator`、`AttributeHandler`。
- **两个命令插件**：`stats`（图形统计）、`dir`（目录查看，须使用 Adapter 模式）。
- **一个图形插件**：`box`（矩形 + 文字组成的复合图形）。
- **属性处理插件**：`box` 的 `fill` 和 `label` 属性语义，以及 undo/redo 与失败回滚。
- **两个树标签插件**：`modified-star`（`*`）与 `box` 类型标签（`(box)`）。
- **两种装配方式**：代码装配（A）和配置装配（B），行为一致、输出一致。
- **测试与设计文档**：兼容性、异常处理、插件隔离、模块依赖图、ADR、代码指标等。

**核心约束**：内核仅依赖公开接口；增加新插件不应修改内核或已有插件；关闭新增插件后，Phase 1 的原有行为和输出保持不变。

## 二、五人分工总览

| 负责人 | 负责模块 | 核心任务 | 主要交付物 | 难度 |
| --- | --- | --- | --- | --- |
| **A** | CLI 内核与扩展机制 | 四个扩展点、注册机制、Phase 1 兼容性重构 | 核心接口、注册表、回归测试、扩展点清单与架构图 | 高 |
| **B** | 命令插件 | `stats`、`dir`、文件系统适配器及独立测试 | 两个命令插件、Adapter 接口与实现、测试和说明 | 中 |
| **C** | 图形与属性插件 | `box`、属性处理器、undo/redo、读回与异常回滚 | `box` 插件、属性扩展实现、边界测试与 ADR | 高 |
| **D** | 树标签与插件加载器 | `modified-star`、`(box)`、代码/配置装配、加载异常处理 | 标签插件、通用加载器、示例配置与测试 | 高 |

## 三、各成员职责

### A · CLI 内核与扩展机制

**开发任务**

1. 定义并完善 `ShapeProvider`、`Command`、`TreeDecorator`、`AttributeHandler` 四个扩展接口及调用契约。
2. 实现注册表、命令分发、图形创建与读回接入、属性处理器分发、树标签调用机制。
3. 为插件提供必要的公开上下文和领域抽象，避免插件依赖内部实现。
4. 重构 Phase 1 内置命令和六种图形的装配方式，确保禁用新增插件时行为和输出不变。
5. 与 C 约定属性操作的事务边界、撤销/重做、失败回滚及复合图形不变量。
6. 与 D 约定插件注册、暂存、校验与提交/回滚的接口。

**交付物**

- 四个扩展点接口及核心实现。
- 扩展点清单：接口名、职责、内核调用位置、实现列表、缺省行为、违约错误处理。
- Phase 1 基础会话回归测试。
- 重构前后 PlantUML 模块依赖图（与 E 配合检查）。

**验收重点**：新增插件不需要修改内核；未装插件时原有 CLI 行为不变。

### B · 命令插件

**开发任务**

1. 实现 `stats`：按当前子节点顺序深度优先遍历，统计叶子图形和容器数量；类型顺序按首次出现顺序；空文档处理正确。
2. 实现 `dir`：列出 CLI 当前工作目录直接子项；包含隐藏项，目录优先、组内按名称升序；空目录及读取失败按题目格式输出。
3. 通过文件系统访问接口与真实适配器实现 `dir`，并使用测试替身隔离文件系统操作。
4. 两个插件各自提供命令名、参数规则和帮助文案，可独立启用或禁用。
5. 确认查询类命令不改变 SVG 文档、dirty 状态及 undo/redo 历史；`dir` 在未初始化文档时仍可使用。

**交付物**

- `stats` 和 `dir` 两个独立命令插件。
- 文件系统访问接口、真实适配器、测试替身。
- 命令单元测试与临时目录集成测试。
- Adapter 模式的角色映射与设计说明。

**验收重点**：`dir` 输出稳定、错误后 CLI 可继续使用，两种装配方式下输出逐字节一致。

### C · `box` 图形与属性扩展

**开发任务**

1. 实现 `box` 图形插件：创建复合图形，内部包含 `rect#<id>-rect` 与 `text#<id>-label`。
2. 支持 `in` 嵌套、整体 `move`、序列化和读回；按题目约束处理 `ungroup`。
3. 注册 `box` 的 `fill` 与 `label` 属性处理器，分别修改内部矩形填充色和文字内容。
4. 与 A 共同明确 `AttributeHandler` 契约：目标图形访问、多个处理器同时命中时的策略、一次 `set` 对应一个 undo 单元。
5. 实现并测试失败回滚，保证处理器部分修改后抛错时文档与 undo/redo 历史保持不变。
6. 处理 ID 冲突、必要子部件被移动/删除、读回结构异常、插件未安装时退化为普通 `g` 等边界情况。

**交付物**

- `box` 图形插件及属性处理器。
- 创建、修改、读写、回滚和撤销/重做测试。
- 属性处理契约 ADR、读回降级与复合图形不变量 ADR。

**验收重点**：在内核和既有插件**零修改**的情况下接入 `box`；一条 `set` 命令可一次撤销/重做，错误不会留下部分修改。

### D · 树标签与插件加载器

**开发任务**

1. 实现 `modified-star` 与 `(box)` 两个独立树标签插件，使原有树渲染器保持不变。
2. 确定 dirty 语义、祖先传播策略和多个标签的拼接顺序，并记录 ADR。
3. 实现代码装配（A）与 `plugins.config.json` 配置装配（B），两者复用同一注册、校验与回滚流程。
4. 配置加载器支持模块路径解析、`enabled: false`、`options` 传递、`contributes` 声明验证。
5. 处理模块不存在、缺少默认导出、清单与注册不一致、激活异常、重复注册、配置无效等情况；插件加载失败时回滚当前插件并继续加载后续插件。
6. 确保加载器不硬编码特定插件包名、导入映射或条件分支。

**交付物**

- 两个标签插件与状态机测试。
- 通用插件加载器、两种装配入口、配置示例。
- 失败路径、重复注册、回滚与双装配一致性测试。
- dirty 语义 ADR、插件清单校验 ADR。

**验收重点**：新增插件时加载器和内核均无需修改；两种装配方式在相同输入下输出逐字节相同。

### E · 最终 Review、集成与验收

**Code Review**

- 检查内核与插件的依赖方向，确认接口隔离和开闭原则。
- 检查是否存在对 `box`、`stats`、`dir` 或标签名称的内核硬编码。
- 检查 Adapter / Command / Decorator 等模式的实际实现与文档说明是否对应。
- 检查属性修改的原子性、错误恢复与全局 ID 唯一性约束。

**集成验收**

- 复验 Phase 1 基础会话与六种图形的兼容性。
- 复验 `stats`、`dir`、`box`、属性修改和两个树标签。
- 复验插件启停、非法配置、重复注册、清单不一致、激活失败、回滚以及启动后继续运行。
- 比对代码装配和配置装配对同一输入的输出，要求逐字节一致。
- 复核 `git diff`：新增插件的接入提交不得修改内核、已有插件；配置装配方式不得修改已有运行代码。

**文档与提交核验**

- 检查 `doc/README.md` 的扩展点清单、两种装配方式、依赖图、模式分析和 ADR。
- 检查 `docs/metrics/` 为脚本基于 Git 历史生成，包含文件职责、行数及圈复杂度增量。
- 检查各阶段 commit 与最终 `p2` tag；协调与第一、第三部分的整体仓库提交。
- 将 Review 问题反馈给 A–D，修复后复验并记录结论。

**交付物**

- Code Review 清单与审查结论。
- 集成验收结果与缺陷追踪（问题、负责人、修复提交、复验状态）。
- 最终文档与指标核验清单。

> E **从接口设计阶段就参与 Review**，但最终签收需等 A–D 完成修复并通过回归测试。

## 四、开发依赖与协作流程

```text
阶段 1：接口设计与约定
A：定义扩展点、注册与事务契约
B/C/D：提出各自插件的接口需求并准备测试
E：审核接口与边界条件
             │
             ▼
阶段 2：并行开发
A：核心重构   B：命令插件   C：box/属性   D：树标签/加载器
             │
             ▼
阶段 3：集成与 Review
E：跨模块测试、Diff 检查、缺陷反馈
A/B/C/D：按问题清单修复
             │
             ▼
阶段 4：最终验收
E：回归复验、文档与指标检查
全组：确认提交与最终 p2 tag
```

### 协作约定

1. **先定接口，再并行实现**：A 与 B/C/D 讨论并冻结首版扩展接口，新增需求通过 Review 协调。
2. **模块归属明确**：原则上由模块负责人修改模块内文件；涉及内核改动先与 A 沟通。
3. **每个模块须自带测试**：不能仅依赖最终人工演示。
4. **功能提交和验收提交分开**：尤其 `box` 接入与两种装配方式，要保留符合题目差异判据的独立提交/分支证据。
5. **不要只在最后做 Review**：E 在接口、首个插件接入和最终集成三个节点审查。

## 五、最终验收 Checklist

### 核心框架（A，E 复核）

- [ ] 四个扩展点均由内核侧接口/抽象类提供，且各有至少一个插件实现。
- [ ] 内核不依赖具体插件实现，未安装新增插件时正常启动。
- [ ] Phase 1 六种图形、内置命令及基础会话输出保持兼容。
- [ ] 扩展点清单包含实际调用位置、缺省行为及违规报错方式。

### 命令插件（B，E 复核）

- [ ] `stats` 的遍历、计数、顺序及空文档输出正确。
- [ ] `dir` 的目录/文件标记、排序、隐藏项、空目录、失败提示正确。
- [ ] `dir` 使用适配器，测试替身与真实文件系统测试均通过。
- [ ] 未初始化 SVG 文档时 `dir` 可用，命令不改变文档或 undo/redo。

### 图形与属性（C，E 复核）

- [ ] `box` 的创建、嵌套、移动、读写、退化策略正确。
- [ ] `fill` 和 `label` 可按语义修改内部子部件。
- [ ] `set` 一次对应一个 undo 单元；失败时整体回滚。
- [ ] ID 冲突、异常读回、内部必要子部件被修改/移走等情况有处理与测试。

### 标签与加载器（D，E 复核）

- [ ] `modified-star` 与 `(box)` 可并存，不修改渲染器。
- [ ] dirty 状态的编辑 → 保存 → 再编辑 → undo 回保存点流程通过测试。
- [ ] A/B 装配使用同一注册和校验路径，运行结果一致。
- [ ] 加载器无具体插件硬编码，按配置顺序加载并处理 `enabled` 和 `options`。
- [ ] 配置无效、找不到模块、无默认导出、清单不符、激活失败、重复注册均有对应测试与错误信息。
- [ ] 单个插件失败时撤销该插件的暂存注册，其他插件仍可加载。

### 集成与交付（E 牵头，全组配合）

- [ ] 基础会话、`box` 会话、`stats`/`dir` 新增会话均通过。
- [ ] 两种装配方式在相同插件、参数、文件、工作目录下输出逐字节一致。
- [ ] `git diff` 满足内核不变和新增插件接入要求。
- [ ] `doc/README.md`、PlantUML 图、至少 3 条 ADR 完整。
- [ ] `docs/metrics/` 由可复现脚本生成，排除构建产物与依赖包。
- [ ] 各过程节点已有普通 commit，最终远程仓库打 `p2` tag。
