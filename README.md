## Lab 1 Phase 2 · CLI 插件式重构分工

本组负责将 Phase 1 的 SVG CLI 重构为插件框架。以 `final` 为兼容性基线，保留各阶段提交，最终在原仓库打 `p2` 标签。

| 角色 | 负责人 | 开发范围 | 主要交付物 |
| --- | --- | --- | --- |
| A · 内核与扩展机制 | @成员A | 定义四个扩展点和注册机制，迁移原有六种图形，负责 `set` 的事务、撤销与失败回滚 | 扩展点接口与清单、注册机制测试、Phase 1 回归结果 |
| B · 命令插件 | @成员B | 分别实现可独立启停的 `stats` 和 `dir`，通过文件系统适配器读取当前工作目录 | 两个命令插件、适配器说明、测试替身与真实临时目录测试 |
| C · 图形与属性插件 | @成员C | 实现 `box` 的创建、读回、结构约束，以及 `fill` 和 `label` 的属性处理器 | `box` 插件、读回与降级测试、与 A 联测的 undo/redo 和异常回滚用例 |
| D · 加载器与树标签 | @成员D | 实现代码装配与配置装配共用的加载流程，处理清单校验、重复注册和激活失败，实现 `modified-star` 与 `(box)` | 加载器及异常路径测试、两个标签插件、dirty 语义说明与测试 |
| E · 集成验收与 Review | @成员E | 建立 `final` 基线，评审接口与提交，验证双装配输出，生成指标并汇总验收证据 | 基线会话、逐字节对比脚本、指标脚本与报告、Git 差异检查记录 |

### 协作约定

- A–D 为各自模块提交实现、单元测试和设计说明。E 从接口评审阶段参与，负责跨模块验收。
- A、C 共同确认一次 `set` 对应一个撤销单元。A、D 共同确认插件激活失败时如何撤销该插件的全部暂存注册。
- 框架就绪后单独提交，再接入 `box`。代码装配和配置装配分别保留演示提交，由 E 核对差异。
- 每位成员记录对 AI 建议的检查与修正。架构图、ADR、扩展点清单和验收说明统一整理到 [设计与验收文档](doc/README.md)。
